## 二、发现并修复的问题

1. **网页包缺少 index.html**：`distribute --package web` 只产出源码式 zip；改用启动器的 `web_build` 命令，产出含 `index.html`/`renpy.wasm` 的完整网页包。
2. **主菜单为英文**：补齐 `translate None strings` 汉化（40 余条），并重写 `main_menu` 为左侧竖排中文菜单。
3. **对白对比度不足**：重绘 `textbox.png`，把底部渐变的起始不透明度从 0 提到 185。
4. **立绘顶部被裁、背景硬边**：立绘缩放至 0.82、底部对齐；羽化遮罩增加顶部 22% 渐隐。
5. **macOS 包启动崩溃**：`guisupport.rpy` 在桌面端会调用 `gui7.generate_gui()`，而发布包不含 launcher 的 `gui7` 模块。改为只保留 `gui.scale`，界面图由 `tools/gen_gui.py` 预生成。此问题 lint 无法发现，只有实际运行才暴露。
6. **第 12 章时间线矛盾**：抢救过程一度出现两套时间（14:20 与次日 04:35），已重写为单线：14:20 剖宫产 → 15:00 入 ICU → 次日 04:35 死亡。
7. **多处编辑导致过渡句丢失**：已在复审中补回（试车、市场、婚宴、账本等衔接处）。

部署要点（踩过的坑）：

## 七、网页版「卡在 loading」的定位与修复（2026-10-20）

**现象**：浏览器打开 GitHub Pages 地址后停在 Ren'Py 启动图，不再前进。

**定位**（读源码 + 网络实测，非推测）：

1. `renpy-pre.js` 的 `loadGameZip()` 用**一次 fetch** 取整个 `game.zip`（33 MB），无超时、无重试、无断点续传；`if (!response.ok) reportError(...)` 之后也没有 return，失败路径只会让流卡住。
2. 从本机到 `gongfpp.github.io` 连续三次请求 `renpy.wasm`，**两次 `SSL_ERROR_SYSCALL`**。同一台机器走 7897 代理访问 Cloudflare 正常，说明是 github.io 这条链路不稳定，不是浏览器问题。
3. 旧构建注册了 Service Worker（`cacheName = '超时'`），一旦某次响应被截断后写入 Cache Storage，客户端会反复命中坏条目，表现为「每次打开都卡在同一处」。

**修复**：`tools/patch_web.py`（构建后必跑）

| 改动 | 验证方式 | 结果 |
| --- | --- | --- |
| `game.zip` 切 5 片（8 MB/片）逐片下载 | 本地 serve `build/web`，Playwright 记录请求 | 5 个分片请求，0 错误 |
| 断流用 Range 续传，最多 6 次；服务端忽略 Range 时回退整片重下 | 拦截 `game.zip.002`，首次只返回 1 MB | 触发 1 次续传，仍正常启动（4.0 s） |
| 停用 SW 并清理旧 Cache Storage | 检查 `index.html` 注入内容 | 注册代码已被替换为注销 + `caches.delete` |
| 90 秒看门狗 | 本地启动测试 | 正常启动时不触发，不产生额外报错 |
| 启动图替换为作品标题图 + 加载提示 | 查看 `build/web/web-presplash.jpg` | 已替换（218 KB） |

**线上复测**（GitHub Pages，冷启动、经代理）：

```
启动成功： 21557 ms，canvas 1280x720
requests: 16（其中分片 5）| errors: 0
```

**遗留**：修复前已打开过该站点的浏览器可能仍持有旧 Service Worker 缓存，需强制刷新一次（Cmd+Shift+R）触发注销逻辑；此后由页面自动清理。

## 八、网页版加载提速（2026-10-20 夜）

用户反馈「开头下载太慢」。实测与拆解后，改动集中在三处：

**1. 字库裁剪（占收益的绝大部分）**

`game.zip` 解包后 43.2 MB，其中三份 Noto CJK 全字库占 32 MB（94%）：

| 文件 | 原大小 | 裁剪后 | 说明 |
| --- | --- | --- | --- |
| NotoSerifSC-Bold.otf | 12.09 MB | — | 全项目无引用，直接删除 |
| NotoSerifSC-Regular.otf | 11.63 MB | 0.68 MB | 按 1892 字（汉字 1724）裁剪 |
| NotoSansSC-Regular.otf | 8.33 MB | 0.48 MB | 同上 |

游戏文本固定、无玩家输入，因此按字符集裁剪是无损的。`game.zip` 33.1 MB → 6.3 MB。

**2. 分片并行 + 提前预取**

原来 Ren'Py 用一次 fetch 拉整个包，且必须等 wasm 编译完才发起，两段下载是串行的。
改为页面加载即开始预取（4 片 × 2 MB，与 wasm 并行），进入内存后再一次写入 `/game.zip`。

**3. 恢复能力不变**

分片仍带 Range 续传与 6 次重试；用「首次只返回 1 MB」的注入测试复验，仍能启动（4.1 s，触发 1 次续传）。

**实测（GitHub Pages，冷启动，同一代理线路）**

| 版本 | 首次传输量 | 两次冷启动耗时 |
| --- | --- | --- |
| 修改前 | ≈ 45 MB | 21.5 s / 83.6 s |
| 修改后 | ≈ 18 MB | 7.8 s / 9.2 s |

改动后不仅更快，波动也小得多（原来同一地址两次差 4 倍）。macOS 包同步从 89 MB 降到 64 MB。

**验证**：裁字后逐屏截图检查（标题页 / 章节卡 / 对白 / 存档菜单），中文无方框；`lint` 0 错误；网页与桌面端启动正常。

**EdgeOne 的结论**：免费版给的 `.edgeone.cool` 是**带一次性 token 的预置域名**，`curl` 不带参数返回 401，带参数 302 后靠 cookie 才放行——不能作为公开分享链接。要公开访问必须绑定自有域名；若要中国大陆节点加速，还需要域名备案。所以 EdgeOne 目前只适合自己预览。

**直连实测（不使用代理，各 2—3 次冷启动）**

| 站点 | 冷启动耗时 |
| --- | --- |
| GitHub Pages | 7.8 / 8.1 / 9.7 s |
| EdgeOne Pages | 12.8 s（单次） |
| Cloudflare Pages | 9.3 / 12.4 / 23.5 s（首次含 DNS/TLS 冷启动） |

三个平台的差距已落在同一量级，说明**瓶颈不再是托管方，而是 18 MB 的初始体积本身**。换平台只解决稳定性，不解决体积。

**部署命令**（token 走环境变量，不落盘）：

```bash
# Cloudflare
CLOUDFLARE_ACCOUNT_ID=<id> CLOUDFLARE_API_TOKEN=<token> \
  wrangler pages deploy build/web --project-name chaoshi-2018 --branch main --commit-dirty=true

# EdgeOne（注意必须指定区域，否则报 Invalid region）
EDGEONE_PAGES_API_REGION=china EDGEONE_PAGES_API_TOKEN=<token> \
  edgeone makers deploy build/web -n chaoshi
```

坑：EdgeOne CLI 若不设 `EDGEONE_PAGES_API_REGION`，会报 `Invalid region: undefined` 并退化成“未登录”；Cloudflare 若用 scoped token，必须同时给 `CLOUDFLARE_ACCOUNT_ID`，否则 `wrangler whoami` 取不到账号。

## 十、大陆直连实测：Cloudflare / GitHub / EdgeOne（2026-10-21 00:15）

测法：Chromium 加 `--no-proxy-server` 强制绕过本机 Clash，从宁波电信线路直连；每个站点 2 次冷启动。
出口核对：`curl --noproxy '*' https://www.cloudflare.com/cdn-cgi/trace` → `ip=123.152.156.72 loc=CN colo=LAX`
（说明大陆到 Cloudflare 免费版被调度到**洛杉矶**节点，不是香港/新加坡）。

**单文件吞吐（renpy.wasm，压缩后约 6 MB）**

| 站点 | 第 1 次 | 第 2 次 |
| --- | --- | --- |
| EdgeOne | ttfb 0.38 s / **2.35 MB/s** | ttfb 0.34 s / 2.33 MB/s |

| Cloudflare Pages | **40 s 超时，只收到 571 KB（14 KB/s）** | 6.06 s / 0.97 MB/s |

| 站点 | 耗时 |
| --- | --- |
| GitHub Pages | 7.6 s / 11.2 s |
