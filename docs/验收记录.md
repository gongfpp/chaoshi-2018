## 二、发现并修复的问题

1. **网页包缺少 index.html**：`distribute --package web` 只产出源码式 zip；改用启动器的 `web_build` 命令，产出含 `index.html`/`renpy.wasm` 的完整网页包。
2. **主菜单为英文**：补齐 `translate None strings` 汉化（40 余条），并重写 `main_menu` 为左侧竖排中文菜单。
3. **对白对比度不足**：重绘 `textbox.png`，把底部渐变的起始不透明度从 0 提到 185。
4. **立绘顶部被裁、背景硬边**：立绘缩放至 0.82、底部对齐；羽化遮罩增加顶部 22% 渐隐。
5. **macOS 包启动崩溃**：`guisupport.rpy` 在桌面端会调用 `gui7.generate_gui()`，而发布包不含 launcher 的 `gui7` 模块。改为只保留 `gui.scale`，界面图由 `tools/gen_gui.py` 预生成。此问题 lint 无法发现，只有实际运行才暴露。
6. **第 12 章时间线矛盾**：抢救过程一度出现两套时间（14:20 与次日 04:35），已重写为单线：14:20 剖宫产 → 15:00 入 ICU → 次日 04:35 死亡。
7. **多处编辑导致过渡句丢失**：已在复审中补回（试车、市场、婚宴、账本等衔接处）。

部署要点（踩过的坑）：

1. **`distribute --package web` 产不出可运行的网页版**——它只打包工程，不含 wasm 运行时。网页版必须用 `renpy.sh launcher web_build <project> --destination <dir>`。
2. **`.nojekyll` 必需**，否则 Pages 会尝试 Jekyll 处理。
3. 该构建为**单线程 wasm**（`renpy.js` 中无 `SharedArrayBuffer` / `pthread`），因此不需要 COOP/COEP 响应头——这正是 GitHub Pages 能跑起来的前提；若改用多线程构建，Pages 无法自定义响应头，需换 Cloudflare Pages / Netlify。
4. 首次把历史推上去前，仓库 778 MB（含 `build/` 下 100 MB 的 wasm 打包与 zip），超过 GitHub 单文件 100 MB 硬限制。已用 `filter-branch --index-filter` 从全部历史移除 `build/`、`gui-*-dists/` 与重复字库，压缩后源码 67 MB、`.git` 57 MB；重写前备份在 `.git/pre-public-backup.bundle`（不入库）。
5. 公开前用 `repo-public-audit` 扫描了全历史：无密钥、无私钥、无本机路径、无手机号/身份证/银行卡。命中的「银行卡号」是 toutiao 文章 URL 里的 19 位数字，「中文隐私词」是小说正文里的「工资卡」等剧情用词，均属误报。
