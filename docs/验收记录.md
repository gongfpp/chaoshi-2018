## 二、发现并修复的问题

1. **网页包缺少 index.html**：`distribute --package web` 只产出源码式 zip；改用启动器的 `web_build` 命令，产出含 `index.html`/`renpy.wasm` 的完整网页包。
2. **主菜单为英文**：补齐 `translate None strings` 汉化（40 余条），并重写 `main_menu` 为左侧竖排中文菜单。
3. **对白对比度不足**：重绘 `textbox.png`，把底部渐变的起始不透明度从 0 提到 185。
4. **立绘顶部被裁、背景硬边**：立绘缩放至 0.82、底部对齐；羽化遮罩增加顶部 22% 渐隐。
5. **macOS 包启动崩溃**：`guisupport.rpy` 在桌面端会调用 `gui7.generate_gui()`，而发布包不含 launcher 的 `gui7` 模块。改为只保留 `gui.scale`，界面图由 `tools/gen_gui.py` 预生成。此问题 lint 无法发现，只有实际运行才暴露。
6. **第 12 章时间线矛盾**：抢救过程一度出现两套时间（14:20 与次日 04:35），已重写为单线：14:20 剖宫产 → 15:00 入 ICU → 次日 04:35 死亡。
7. **多处编辑导致过渡句丢失**：已在复审中补回（试车、市场、婚宴、账本等衔接处）。

## 七、网页版「卡在 loading」的定位与修复（2026-10-20）

**现象**：浏览器打开 GitHub Pages 地址后停在 Ren'Py 启动图，不再前进。

**定位**（读源码 + 网络实测，非推测）：

1. `renpy-pre.js` 的 `loadGameZip()` 用**一次 fetch** 取整个 `game.zip`（33 MB），无超时、无重试、无断点续传；`if (!response.ok) reportError(...)` 之后也没有 return，失败路径只会让流卡住。
2. 从本机到 `gongfpp.github.io` 连续三次请求 `renpy.wasm`，**两次 `SSL_ERROR_SYSCALL`**。同一台机器走 7897 代理访问 Cloudflare 正常，说明是 github.io 这条链路不稳定，不是浏览器问题。
3. 旧构建注册了 Service Worker（`cacheName = '超时'`），一旦某次响应被截断后写入 Cache Storage，客户端会反复命中坏条目，表现为「每次打开都卡在同一处」。

**修复**：`tools/patch_web.py`（构建后必跑）

| 改动 | 验证方式 | 结果 |
| --- | --- | --- |
| `game.zip` 切 5 片（8 MB/片）逐片下载 | 本地 serve `build/web`，Playwright 记录请求 | 5 个分片请求，0 错误 |
| 断流用 Range 续传，最多 6 次；服务端忽略 Range 时回退整片重下 | 拦截 `game.zip.002`，首次只返回 1 MB | 触发 1 次续传，仍正常启动（4.0 s） |
| 停用 SW 并清理旧 Cache Storage | 检查 `index.html` 注入内容 | 注册代码已被替换为注销 + `caches.delete` |
| 90 秒看门狗 | 本地启动测试 | 正常启动时不触发，不产生额外报错 |
| 启动图替换为作品标题图 + 加载提示 | 查看 `build/web/web-presplash.jpg` | 已替换（218 KB） |

**线上复测**（GitHub Pages，冷启动、经代理）：

```
启动成功： 21557 ms，canvas 1280x720
requests: 16（其中分片 5）| errors: 0
```

**遗留**：修复前已打开过该站点的浏览器可能仍持有旧 Service Worker 缓存，需强制刷新一次（Cmd+Shift+R）触发注销逻辑；此后由页面自动清理。

## 八、网页版加载提速（2026-10-20 夜）

用户反馈「开头下载太慢」。实测与拆解后，改动集中在三处：

**1. 字库裁剪（占收益的绝大部分）**

`game.zip` 解包后 43.2 MB，其中三份 Noto CJK 全字库占 32 MB（94%）：

| 文件 | 原大小 | 裁剪后 | 说明 |
| --- | --- | --- | --- |
| NotoSerifSC-Bold.otf | 12.09 MB | — | 全项目无引用，直接删除 |
| NotoSerifSC-Regular.otf | 11.63 MB | 0.68 MB | 按 1892 字（汉字 1724）裁剪 |
| NotoSansSC-Regular.otf | 8.33 MB | 0.48 MB | 同上 |

游戏文本固定、无玩家输入，因此按字符集裁剪是无损的。`game.zip` 33.1 MB → 6.3 MB。

**2. 分片并行 + 提前预取**

原来 Ren'Py 用一次 fetch 拉整个包，且必须等 wasm 编译完才发起，两段下载是串行的。
改为页面加载即开始预取（4 片 × 2 MB，与 wasm 并行），进入内存后再一次写入 `/game.zip`。

**3. 恢复能力不变**

分片仍带 Range 续传与 6 次重试；用「首次只返回 1 MB」的注入测试复验，仍能启动（4.1 s，触发 1 次续传）。

**实测（GitHub Pages，冷启动，同一代理线路）**

| 版本 | 首次传输量 | 两次冷启动耗时 |
| --- | --- | --- |
| 修改前 | ≈ 45 MB | 21.5 s / 83.6 s |
| 修改后 | ≈ 18 MB | 7.8 s / 9.2 s |

改动后不仅更快，波动也小得多（原来同一地址两次差 4 倍）。macOS 包同步从 89 MB 降到 64 MB。

**验证**：裁字后逐屏截图检查（标题页 / 章节卡 / 对白 / 存档菜单），中文无方框；`lint` 0 错误；网页与桌面端启动正常。

**EdgeOne 的结论**：免费版给的 `.edgeone.cool` 是**带一次性 token 的预置域名**，`curl` 不带参数返回 401，带参数 302 后靠 cookie 才放行——不能作为公开分享链接。要公开访问必须绑定自有域名；若要中国大陆节点加速，还需要域名备案。所以 EdgeOne 目前只适合自己预览。

**补充实测（2026-10-22）——token 有效期只有 3 小时**：

带参数请求返回的是 302，`Set-Cookie` 里 `eo_token` / `eo_time` 都是 `Max-Age=10800`（3 小时）。也就是说每次 `makers deploy` 换来的预览链接只活 3 小时，之后固定报 `401 X-EOP-MSG: eo_time expired`。10-20 那次签发的 `eo_time=1792511964`（2026-10-20 23:59）到 10-22 15:21 实测已过期，符合这个寿命。

因此 EdgeOne 的定位只能是**临时预览**：要给别人看，每次都得重新部署一次（重新上传 build/web，约 40 秒）拿新 token；想长期固定必须绑自有域名。

2026-10-22 15:29 重新部署（`dp46jfa75ve5`），确认 EdgeOne 上已是最新构建 `20d716a`；同域 `renpy.wasm` 带 Range 请求返回 `206`（支持分段下载），埋点端点指向 `https://chaoshi-analytics.gong7968.workers.dev/api/collect`。API Token 现已存 `.secrets/edgeone.env`（600 权限、`.gitignore` 已排除），部署时可 `set -a && . ./.secrets/edgeone.env && set +a` 直接取用。

## 十一、开屏重做与装载链路加固（2026-10-22）

### 症状

线上（尤其 Cloudflare Pages）经常停在 Ren'Py 原生英文状态条，最后弹出
`Download error: network error`；偶尔白屏。GitHub Pages 上多数时候能进，
但只要慢就同样失败。

### 三个根因

| # | 根因 | 证据 |
|---|---|---|
| 1 | 分片下载给每片 2 MB 下 60 秒墙钟硬超时，要求链路持续 ≥34 KB/s | 旧 `patch_web.py` 的 `setTimeout(ctrl.abort, 60000)` |
| 2 | Cloudflare Pages 对 `Range: bytes=…` 返回 **200 全量**（GitHub Pages 返回 206），超时后只能从 0 重下，6 次重试必然耗尽 | `curl -H 'Range: bytes=1000000-'` 对比两个站 |
| 3 | 引擎进度只统计 `renpy.data`（14.4 MB），21.6 MB 的 `renpy.wasm` 在此之前静默下载完，弱网下等于盯着 0% 干等 | `renpy-pre.js` 的 `updateDownloadProgress` 只认 `dataSize` |

### 改动

- **自绘开屏层** `tools/web/chaoshi-loader.js`：黑场 → 片名 → 台词 → 底图 →
  进度面板的电影感片头；中文文案；错误态给「重新加载 / 换 GitHub 线路 /
  换 Cloudflare 线路」，并附「技术细节」折叠（含原生 `#statusTextDiv` 尾部）。
  原生 `#statusDiv` 保留在 DOM 里但隐藏，只当数据源。
- **按字节记账的总进度**：`window.CHAOSHI_SIZES` 在构建时写入
  `renpy.wasm + renpy.data + game.zip` 的真实体积（本项目 43.1 MB），
  wasm 用 `fetch`/`XHR` 旁路观测（`Response.clone()`，不重复下载）。
- **下载器**：1 MB/片、并发 3、空闲 15 秒才判失败（不是墙钟）、Range 续传、
  服务端忽略 Range 时跳过已读字节、落盘后核对字节数。
- **后台预取**：进主菜单 2 秒后按优先级把 73 个散装资源拉进 HTTP 缓存，
  并发 2、12 MB 预算、`saveData`/2G/3G 自动降级、`?noprefetch=1` 可关。
- **service worker 注销**：`getRegistrations().unregister()` + 清 Cache Storage。
- **启动图**：不再往图里烧字（原先用已子集化的字库渲染，「首/若/此」是方框），
  文字全部由 HTML 层用系统字体渲染；q80 渐进式 JPEG，109 KB。
- **按需资源重试** `game/game/web_boot.rpy`：包一层 `RenPyWeb.dl_new`，
  20 秒无数据才中断、指数退避、后两次换镜像；彻底失败时把英文报错换中文。

## 十二、生产埋点端点上线（2026-10-22 下午）

第十一节遗留的「三个静态站 `/api/collect` 都是 404」已解决。原因是令牌缺少
D1 权限；补上后建了真正的落库端点。

### 构成

| 层 | 实现 |
|---|---|
| 数据库 | D1 `chaoshi_events`（uuid `a7c12d4b-…-e5d361d75bd5`，APAC） |
| 端点 | Worker `chaoshi-analytics` → `https://chaoshi-analytics.gong7968.workers.dev` |
| 表 | `events`（event/vid/sid/seq/run_id/build/site/chapter/choice/opt/ending/ms/reason/ref/test/t_client/t_server/raw） |
| 看板 | 同一个 Worker 托管 `/`，与 `/api/stats` 同源，另有 `build/web/dash.html` 可挂到静态站 |
| 令牌 | `ANALYTICS_TOKEN` 用 `wrangler secret` 写入，明文只在 `build/analytics/token.txt`（已 git 忽略） |

### 接口

```
POST /api/collect   {"events":[...]}          → {"ok":true,"kept":N,"sent":M}
GET  /api/stats?token=…&days=30               → 与 tools/collector.py 同构的聚合结果
GET  /healthz                                 → 存活与总条数
```

`kept` 取自 `meta.changes` 之和，不是「提交了几条」——`sendBeacon` 在 `pagehide`
会重发同一批，靠 `(sid, seq)` 唯一索引去重，实测重发返回 `kept:0`。

### 同时修掉的两个采集缺陷

1. **关键事件被批处理压住**：原来只有队列 ≥8 条或每 8 秒才 flush，玩家关页时
   `game_ready`/`chapter_complete` 会烂在队列里。现在这些里程碑（含
   `page_view`/`run_start`/`choice_pick`/`ending_*`/`error`）走 `IMMEDIATE` 立即发，
   定时器缩到 4 秒。
2. **线上/本地混流**：tracker 按 hostname 分流 —— `localhost`/`127.0.0.1` 走同源
   `/api/collect`（`tools/collector.py`），其余一律发 Worker，调试不污染生产库。
